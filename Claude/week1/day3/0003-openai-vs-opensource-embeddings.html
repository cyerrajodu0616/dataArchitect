OpenAI Embeddings vs Open-Source (BGE, E5, Instructor) & Deep Dive Architecture

Week 1, Day 3 — cost, latency, quality, privacy, MRL, and 2-stage retrieval

Yesterday's lesson settled which metric to use. Today is one level up the stack: which model produces the vectors in the first place, and whether that model should live behind an API call or on hardware you own. This is a build-vs-buy decision — the exact shape of decision you've made a hundred times as a data engineer, just with a different noun (model instead of database, GPU instead of warehouse cluster).

Retail framing
Scenario
A retail product catalog has 4M SKUs, each re-embedded monthly as descriptions/attributes change, plus ~200K customer search queries embedded per day at request time. Two very different traffic shapes — bulk/batch vs real-time/low-latency — and the right embedding model choice can differ for each.

1. The Two Camps

API-based (closed): OpenAI's text-embedding-3-small and text-embedding-3-large. You send text over the network, get a vector back. No infrastructure to run.

Open-source (self-hosted): BGE (BAAI General Embedding), E5 (Microsoft), Instructor (task-instruction-conditioned embeddings) — all distributed as weights you download and run yourself, typically via sentence-transformers or a dedicated inference server (TGI, vLLM, Infinity, TEI). You own the compute, scaling, and upgrades.

2. Deep Dive: Bi-Encoder vs. Cross-Encoder Mechanics

Embedding models like OpenAI text-embedding-3, BGE, and E5 are Bi-Encoders (Dual-Tower Transformers). Queries ($q$) and documents ($d$) are passed through independent transformer passes:

$$\text{Score}_{\text{bi}}(q, d) = \langle E_Q(q), E_D(d) \rangle = \mathbf{v}_q \cdot \mathbf{v}_d$$

  • Mechanism: $E_Q$ and $E_D$ map text independently into vectors $\mathbb{R}^d$.
  • Computational Complexity:
    • Offline Ingestion: $O(N)$ transformer forward passes to pre-compute vector index for $N$ documents.
    • Query Time: $O(1)$ query forward pass + $O(\log N)$ Approximate Nearest Neighbor (ANN) index search (HNSW/IVFFlat). Total latency: <15ms.
  • The Information Bottleneck: Because $q$ and $d$ do not interact inside self-attention layers, subtle nuances (e.g. "lightweight boots BUT NOT steel toe") get compressed into a single static point, causing precision loss.

Cross-Encoder Physics (Stage 2: Precision Reranking)

In a Cross-Encoder (like bge-reranker-large), the query and document are concatenated and fed into a single Transformer together:

$$\text{Score}_{\text{cross}}(q, d) = \text{Transformer}(\text{concat}(q, [\text{SEP}], d)) \to \text{Relevance Score} \in [0, 1]$$

  • Mechanism: Every token in the query attends to every single token in the document across all cross-attention layers.
  • Computational Complexity: Cannot pre-compute static vectors or index in vector DBs! Requires $K$ full Transformer evaluations for $K$ candidate documents ($O(K \cdot L^2)$ attention operations).
The Golden 2-Stage Production Pattern
User Query: "red leather running shoes size 10"
       │
       ▼
[ Stage 1: Bi-Encoder Vector Search ]  ---> Pulls Top K=100 Candidates (<15ms via pgvector)
       │
       ▼
[ Stage 2: Cross-Encoder Reranker ]    ---> Reranks 100 pairs jointly (<40ms via bge-reranker)
       │
       ▼
[ Top 5 Final Context Chunks ]         ---> Sent to LLM Generator

3. Model Prefixes & Matryoshka Embeddings (MRL)

Asymmetric Retrieval & Prefixes

  • Symmetric Matching: Comparing sentence vs. sentence (e.g., duplicate article detection). Both texts have identical length and role.
  • Asymmetric Matching: Short Search Query ($L \approx 5$ tokens) vs. Long Document Chunk ($L \approx 300$ tokens).
  • Prefix Requirement: Models like E5 and BGE learned distinct positional and role embeddings during contrastive training: 
    # E5 Example: Must include prefixes!
query_vec = model.encode("query: mens trail running boots")
doc_vec = model.encode("passage: The Waterproof Alpine Boot features...")

    ⚠️ Warning: Omitting query: or passage: causes vectors to land in mismatched subspaces, dropping nDCG@10 by up to 30%.

Matryoshka Representation Learning (MRL) Internals

MRL models (like OpenAI text-embedding-3) apply a nested loss function across multiple sub-dimensions:

$$\mathcal{L}_{\text{MRL}} = \sum_{d \in \{256, 512, 1024, 1536\}} w_d \cdot \mathcal{L}_{\text{contrastive}}\left(\mathbf{v}_{:d}^{(q)}, \mathbf{v}_{:d}^{(d)}\right)$$

  • Early dimensions ($\mathbf{v}_{[:256]}$) capture broad semantic categories (e.g., "footwear vs cookware").
  • Later dimensions ($\mathbf{v}_{[256:1536]}$) capture fine-grained distinctions (e.g., "waterproof vs water-resistant").
Truncation & Re-Normalization Code
import numpy as np

def truncate_mrl_vector(vec_1536: np.ndarray, target_dim: int = 256) -> np.ndarray:
    truncated = vec_1536[:target_dim]
    # Crucial: Must re-normalize to unit length for cosine similarity!
    return truncated / np.linalg.norm(truncated)

Architect Impact: Truncating 1536d → 256d retains ~98.5% accuracy while reducing pgvector RAM footprint by 6x and accelerating ANN index scans by 3x.

4. Production QPS Crossover Math: API vs. Self-Hosted (TEI)

Scenario: 10 Million SKUs (100 tokens/SKU). Monthly Batch Re-embedding + Real-Time Queries ($Q$ QPS, 15 tokens/query).

  • OpenAI text-embedding-3-small API: Batch re-embed = 1B tokens × $0.01 / 1M = $10.00 / month.
    Real-time API cost = $\frac{Q \times 15 \times 2,592,000}{1,000,000} \times \$0.02 = \mathbf{\$0.7776 \times Q \text{ / month}}$.
  • Self-Hosted TEI on AWS GPU (g5.xlarge - NVIDIA A10G): Fixed cost = $724.32 / month ($1.006/hr). TEI container serves ~1,200 QPS at <10ms latency.
The QPS Crossover Derivation
$$\$0.7776 \times Q = \$724.32 \implies Q = \frac{724.32}{0.7776} \approx \mathbf{931.5 \text{ QPS}}$$ 
Monthly Cost ($)
 ^
 |                                                  / (OpenAI API Cost)
 |                                                 /
 |                                                /
$724 |------------------------------------------/---------- (Self-Hosted GPU Cost)
 |                                             /|
 |__________________________________________/__|____________________> QPS
                                          0   931 QPS
  • For $Q < 930$ QPS: OpenAI API wins on cost AND operations. At 100 QPS, API costs only ~$77/month vs. $724/month for dedicated GPU hardware. Zero MLOps, zero cluster maintenance.
  • For $Q > 930$ QPS: Self-Hosted TEI on GPU wins. At 2,000 QPS, OpenAI API costs ~$1,555/month vs. $1,448/month for 2x GPU instances, providing higher QPS capacity, lower tail latency, and 100% PII data sovereignty.

5. Data Privacy, Governance & Compliance Spectrum

Privacy Level Architecture Compliance & Data Boundary
Level 1: Public API OpenAI Public Endpoint (api.openai.com) Data leaves network perimeter. 30-day encrypted retention logs. Risk of PII exposure.
Level 2: Enterprise Cloud VPC Azure OpenAI / AWS Bedrock (PrivateLink) Traffic stays inside enterprise VNet. Zero data retention. Customer-Managed Keys (CMK).
Level 3: Self-Hosted Air-Gapped BGE / E5 on PyTorch / TEI in K8s 100% Data Sovereignty. Zero network egress. Ideal for healthcare (HIPAA), PCI-DSS, defense.

bi_vs_cross_encoder.py 
"""
Week 1, Day 3 — Deep Dive Code 1: Bi-Encoder vs. Cross-Encoder 2-Stage Retrieval

Demonstrates:
  Stage 1: Bi-Encoder vector retrieval (O(1) index lookup to get top K candidates)
  Stage 2: Cross-Encoder joint re-ranking (O(K) transformer cross-attention pass)

Requires:
  uv add sentence-transformers numpy
"""

import numpy as np
from sentence_transformers import SentenceTransformer, CrossEncoder

# 1. Load Bi-Encoder (Stage 1) and Cross-Encoder (Stage 2)
print("Loading Stage 1 Bi-Encoder (bge-small-en-v1.5)...")
bi_encoder = SentenceTransformer("BAAI/bge-small-en-v1.5")

print("Loading Stage 2 Cross-Encoder (bge-reranker-base)...")
cross_encoder = CrossEncoder("BAAI/bge-reranker-base")

# 2. Product Catalog (Documents)
DOCUMENTS = [
    "Men's Waterproof Trail Running Boots - Heavy Duty Steel Toe",
    "Women's Lightweight Cushion Running Sneakers - Blue / Size 8",
    "Workwear Denim Jeans with Reinforced Steel Rivets",
    "Stainless Steel Non-Stick 10-Piece Kitchen Cookware Set",
    "Men's Casual Leather Slip-On Loafers - Brown",
]

QUERY = "steel toe boots for work"

print(f"\nQuery: '{QUERY}'\n" + "-"*50)

# --- STAGE 1: Bi-Encoder Retrieval (Top 4 Candidates) ---
# Note: BGE requires query prefix for asymmetric search
query_embedding = bi_encoder.encode(
    f"Represent this sentence for searching relevant passages: {QUERY}"
)
doc_embeddings = bi_encoder.encode(DOCUMENTS)

# Cosine similarity: dot(q, d) since vectors are L2-normalised
scores_stage1 = np.dot(doc_embeddings, query_embedding) / (
    np.linalg.norm(doc_embeddings, axis=1) * np.linalg.norm(query_embedding)
)

top_k_indices = np.argsort(scores_stage1)[::-1][:4]

print("\n--- STAGE 1: Bi-Encoder Vector Search Results (Top 4) ---")
candidate_docs = []
for rank, idx in enumerate(top_k_indices):
    score = scores_stage1[idx]
    doc_text = DOCUMENTS[idx]
    candidate_docs.append(doc_text)
    print(f"Rank {rank+1} (Score: {score:.4f}): {doc_text}")

# --- STAGE 2: Cross-Encoder Re-ranking ---
# Build (Query, Document) pairs for joint cross-attention scoring
pairs = [[QUERY, doc] for doc in candidate_docs]
rerank_scores = cross_encoder.predict(pairs)

reranked_indices = np.argsort(rerank_scores)[::-1]

print("\n--- STAGE 2: Cross-Encoder Reranked Final Results ---")
for rank, idx in enumerate(reranked_indices):
    score = rerank_scores[idx]
    doc_text = candidate_docs[idx]
    print(f"Final Rank {rank+1} (Rerank Score: {score:.4f}): {doc_text}")

mrl_and_prefixes.py 
"""
Week 1, Day 3 — Deep Dive Code 2: Matryoshka Embeddings (MRL) & Prefix Mechanics

Demonstrates:
  1. Truncating 1536-dim OpenAI MRL embeddings down to 512d & 256d with re-normalization
  2. The impact of prefixes ('query: ' vs 'passage: ') on open-source E5/BGE models

Requires:
  uv add openai numpy python-dotenv sentence-transformers
"""

import numpy as np
from dotenv import load_dotenv
from openai import OpenAI
from sentence_transformers import SentenceTransformer

load_dotenv()
client = OpenAI()

# --- PART 1: Matryoshka Representation Learning (MRL) Vector Truncation ---
print("=== PART 1: OpenAI MRL Vector Truncation (1536d -> 512d -> 256d) ===")

TEXT_A = "Customer requested a refund on footwear due to sizing issue."
TEXT_B = "The customer returned the shoes because they didn't fit."
TEXT_C = "The warehouse received a new shipment of stainless steel cookware."

def get_openai_vec(text: str) -> np.ndarray:
    resp = client.embeddings.create(model="text-embedding-3-small", input=text)
    return np.array(resp.data[0].embedding)

vec_a_1536 = get_openai_vec(TEXT_A)
vec_b_1536 = get_openai_vec(TEXT_B)
vec_c_1536 = get_openai_vec(TEXT_C)

def truncate_and_normalize(vec: np.ndarray, dim: int) -> np.ndarray:
    """Truncate MRL vector to `dim` and re-normalize to unit length."""
    truncated = vec[:dim]
    return truncated / np.linalg.norm(truncated)

def cos_sim(a: np.ndarray, b: np.ndarray) -> float:
    return float(np.dot(a, b))   # both unit vectors, so dot == cosine

for dim in [1536, 512, 256]:
    a = truncate_and_normalize(vec_a_1536, dim)
    b = truncate_and_normalize(vec_b_1536, dim)
    c = truncate_and_normalize(vec_c_1536, dim)

    sim_ab = cos_sim(a, b)
    sim_ac = cos_sim(a, c)

    print(f"\n--- Dimension {dim:4d} ---")
    print(f"  Sim(Shoes Refund, Returned Shoes) : {sim_ab:.5f}")
    print(f"  Sim(Shoes Refund, Cookware)       : {sim_ac:.5f}")
    print(f"  Margin (Related vs Irrelevant)    : {sim_ab - sim_ac:.5f}")


# --- PART 2: Asymmetric Model Prefixes (E5 / BGE) ---
print("\n\n=== PART 2: Asymmetric Model Prefixes (E5 Model) ===")
e5_model = SentenceTransformer("intfloat/e5-small-v2")

query   = "shoes return policy"
passage = "Customers may return footwear within 30 days of purchase for a full refund."

# Scenario A: WITH correct prefixes
q_correct = e5_model.encode(f"query: {query}")
p_correct = e5_model.encode(f"passage: {passage}")
sim_with = float(
    np.dot(q_correct, p_correct) /
    (np.linalg.norm(q_correct) * np.linalg.norm(p_correct))
)

# Scenario B: WITHOUT prefixes (wrong — vectors land in mismatched subspace)
q_wrong = e5_model.encode(query)
p_wrong = e5_model.encode(passage)
sim_without = float(
    np.dot(q_wrong, p_wrong) /
    (np.linalg.norm(q_wrong) * np.linalg.norm(p_wrong))
)

print(f"Similarity WITH 'query:' and 'passage:' prefixes : {sim_with:.5f}")
print(f"Similarity WITHOUT prefixes                     : {sim_without:.5f}")
print(f"Accuracy penalty for omitting prefixes           : {(sim_with - sim_without):.5f}")

qps_crossover_sim.py 
"""
Week 1, Day 3 — Deep Dive Code 3: Production QPS Crossover & Cost Simulator

Simulates monthly costs of OpenAI Embedding API vs. Self-Hosted GPU TEI Container
based on input QPS, token lengths, GPU instance hourly rates, and dataset sizes.

No external libraries required — pure Python math.

Run:
  python Claude/week1/day3/qps_crossover_sim.py
"""

def calculate_costs(
    num_skus: int          = 10_000_000,  # 10M SKU catalog
    sku_token_len: int     = 100,         # avg tokens per product description
    query_token_len: int   = 15,          # avg tokens per search query
    qps_target: float      = 500.0,       # real-time queries per second
    openai_batch_rate_per_m: float  = 0.01,   # $/M tokens (Batch API)
    openai_realtime_rate_per_m: float = 0.02, # $/M tokens (Real-Time API)
    gpu_hourly_cost: float = 1.006,       # AWS g5.xlarge (1x NVIDIA A10G)
    gpu_max_qps_capacity: int = 1200      # TEI container throughput ceiling
):
    print("="*65)
    print("      ENTERPRISE EMBEDDING COST & QPS CROSSOVER CALCULATOR      ")
    print("="*65)
    print(f"Catalog Size       : {num_skus:,} SKUs ({sku_token_len} tokens/SKU)")
    print(f"Real-Time Traffic  : {qps_target} Queries/Sec ({query_token_len} tokens/query)")
    print(f"GPU Host Hardware  : AWS g5.xlarge (${gpu_hourly_cost:.3f}/hr)")
    print("-" * 65)

    # 1. Batch Monthly Re-embed Cost (one full catalog pass per month)
    total_batch_tokens = num_skus * sku_token_len
    batch_cost_openai  = (total_batch_tokens / 1_000_000) * openai_batch_rate_per_m

    # 2. Real-time Monthly Query Cost
    seconds_in_month   = 30 * 24 * 3600         # 2,592,000 seconds
    monthly_queries    = qps_target * seconds_in_month
    total_query_tokens = monthly_queries * query_token_len
    realtime_cost_openai = (total_query_tokens / 1_000_000) * openai_realtime_rate_per_m

    total_openai_monthly = batch_cost_openai + realtime_cost_openai

    # 3. Self-Hosted GPU Cost (fixed monthly regardless of query volume)
    gpus_needed       = max(1, int((qps_target + gpu_max_qps_capacity - 1) // gpu_max_qps_capacity))
    total_gpu_monthly = gpus_needed * (gpu_hourly_cost * 24 * 30)

    # 4. Exact Crossover QPS Derivation
    # Solve: Q * query_tokens * seconds/month / 1M * realtime_rate = gpu_monthly_cost
    # => Q = gpu_monthly_cost / (query_tokens * seconds/month / 1M * realtime_rate)
    tokens_per_qps_month = query_token_len * seconds_in_month
    api_cost_per_qps     = (tokens_per_qps_month / 1_000_000) * openai_realtime_rate_per_m
    crossover_qps        = (gpu_hourly_cost * 24 * 30) / api_cost_per_qps

    print(f"1. OpenAI Monthly Cost Breakdown:")
    print(f"   - Catalog Re-embed Batch (1B tokens) : ${batch_cost_openai:,.2f}")
    print(f"   - Real-Time Queries ({total_query_tokens/1e6:.1f}M tokens): ${realtime_cost_openai:,.2f}")
    print(f"   -> TOTAL OPENAI COST                 : ${total_openai_monthly:,.2f} / month")
    print(f"\n2. Self-Hosted GPU (TEI) Monthly Cost:")
    print(f"   - GPUs Required ({gpus_needed}x A10G)           : ${total_gpu_monthly:,.2f} / month")
    print("-" * 65)

    if total_openai_monthly < total_gpu_monthly:
        savings = total_gpu_monthly - total_openai_monthly
        print(f"VERDICT at {qps_target} QPS : OPENAI API WINS (Saves ${savings:,.2f}/mo over self-hosting)")
    else:
        savings = total_openai_monthly - total_gpu_monthly
        print(f"VERDICT at {qps_target} QPS : SELF-HOSTED GPU WINS (Saves ${savings:,.2f}/mo over OpenAI)")

    print(f"\nEXACT CROSSOVER THRESHOLD: {crossover_qps:.1f} QPS")
    print(f"  • Below {crossover_qps:.0f} QPS -> Managed OpenAI API is cheaper.")
    print(f"  • Above {crossover_qps:.0f} QPS -> Self-hosted GPU container is cheaper.")
    print("="*65)


if __name__ == "__main__":
    # Run at three different traffic levels to see verdict flip
    for qps in [100.0, 500.0, 1500.0]:
        calculate_costs(qps_target=qps)
        print()
