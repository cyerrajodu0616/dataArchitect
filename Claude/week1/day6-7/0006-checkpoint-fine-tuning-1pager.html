ARCHITECTURAL DECISION RECORD (ADR-001)

Title: Embedding Model Selection & Fine-Tuning Strategy for Enterprise Retail Search vs Personal Agent
Author: Yc (AI Data Platform Architect)
Status: Approved / Production

1. Context & Business Problem

Vector embeddings convert unstructured text into dense floating-point representations where semantic similarity corresponds to mathematical proximity. In a retail platform (4M SKUs, 200k daily search queries), embedding quality directly impacts search relevance, customer conversion, and infrastructure costs. For our internal Personal Agent (~10k chunks, low QPS), operational simplicity dominates.

2. Evaluation of Options

  • Option A (Closed API - OpenAI text-embedding-3-small): $0.02 / 1M tokens. Zero MLOps overhead. 1536 dimensions (supports MRL truncation to 512/256). Pre-normalized unit vectors allow dot product $\equiv$ cosine similarity.
  • Option B (Self-Hosted Open Source - BGE / E5): $0 per token API fee. Requires dedicated PyTorch / TEI GPU container hosting. Allows data sovereignty / PII compliance and custom fine-tuning.
  • Option C (Domain Fine-Tuning): Contrastive learning with Triplet Loss / MNRLoss on open-source weights using proprietary retail pairs.

3. Decision & Trade-Off Matrix

Use Case Selected Approach Key Driver
Personal Agent OpenAI text-embedding-3-small + Cosine Sim (pgvector) Negligible cost (<$0.05/yr), zero MLOps burden.
Retail Batch Catalog OpenAI Batch API ($0.01 / 1M tokens) Monthly re-embed of 4M SKUs costs ~$6. API beats GPU ownership.
High QPS / PII Queries Self-Hosted BGE on GPU + Hybrid Search (BM25) Data privacy, <15ms tail latency, GPU QPS amortization.

4. Fine-Tuning Decision Boundary

Do NOT fine-tune embeddings unless Hybrid Search (BM25 + Dense Vector) and 2-stage Cross-Encoder Reranking fail to meet precision targets on domain-specific benchmarks. Reranking solves 90% of retrieval relevance issues without the cost of maintaining custom PyTorch pipelines.
