Which Framework — And the Case for None of Them

Week 4, Day 2 — four shapes, and the four requirement changes that decide between them

The four things you're choosing between

Raw — you call the model's API yourself, in your own loop. No framework at all. Like writing SQL by hand instead of using an ORM.

Chain (LangChain) — a fixed pipeline. Step, step, step, done. Like a shell script.

Graph (LangGraph) — the state machine from Day 1. Nodes and edges, edges may point backwards.

Crew (CrewAI, AutoGen) — several specialised agents that talk to each other. Like a team with job titles.

1. Why Feature Tables Are Useless Here

Every framework comparison you'll read is a grid of checkmarks. They're all nearly full, because every framework can do everything if you push hard enough. The grid tells you nothing about which to pick.

The question that actually decides it
When the requirements change, which one needs an edit and which one needs a rewrite?

That's knowable from the shape of the code, before you've written anything — which is exactly what makes it useful up front rather than in a retrospective.

2. The Four Shapes, Side by Side

Same job — the refund agent from Day 1 — reduced to just its control flow:

# RAW — you own the loop def handle(request): state = {"request": request} for _ in range(MAX_TURNS): # your loop, your rules action = call_model(state) # ask the model what to do next if action.done: return action.answer state[action.tool] = run_tool(action) # you dispatch the tool return escalate(state)
# CHAIN — a fixed pipeline pipeline = classify | lookup_order | check_policy | decide result = pipeline.invoke({"request": request}) # there is no way to express "go back to classify"
# GRAPH — nodes and edges, edges may point backwards g.add_node("classify", classify) g.add_node("ask_clarify", ask_clarify) g.add_conditional_edges("classify", route) # route() picks the next node g.add_edge("ask_clarify", "classify") # <-- backwards result = g.compile(checkpointer=pg).invoke(state, thread_id=case_id)
# CREW — specialists with roles, talking to each other classifier = Agent(role="Intent classifier", goal="...") policy = Agent(role="Policy expert", goal="...") crew = Crew(agents=[classifier, policy], process=Process.sequential) result = crew.kickoff({"request": request}) # who talks to whom, and when it stops, is largely the framework's decision
The one line that tells you the most
Look at the last comment in each block. RAW says "your loop, your rules". CREW says "the framework's decision". That axis — how much control flow you own versus how much is decided for you — predicts almost everything else, including how hard each is to debug at 2am.

3. Four Changes That Actually Happen

These aren't hypotheticals. They're the four requirements that land on every agent project, usually in this order.

Don't read that chart as a ranking
The chart assumes all four changes arrive. That's a forecast, and it's yours to make. The mistake isn't picking the wrong framework — it's picking one before you know which of those four changes are coming.

And note where RAW's 8 points come from: changes 2 and 3, which are the same underlying requirement (durable, resumable state). If your agent doesn't need to pause or survive restarts, RAW's score drops to 2 and it becomes the cheapest option on the page.

4. The Part Feature Tables Leave Out

RAW is underrated

A tool-calling loop is about 40 lines. You own it, you can read all of it, and it doesn't break on a minor version bump. For a single-purpose agent with two tools this is very often the right answer — and saying so in an interview reads as judgement, not inexperience.

CHAIN is not obsolete

For a genuinely fixed pipeline — summarise, extract, format — a chain is clearer than a graph, because it cannot express things you don't want. Constraint is a feature. Reach for a graph when you need a backward edge, not because it's newer.

CREW is the one to be most careful with

Why multi-agent is appealing and hard
Crews mirror how a human team works, and that intuition is exactly what makes them difficult to operate. Control flow becomes emergent — who speaks next, when it stops, and how disagreement resolves are decided by the framework and by the models, at runtime.

That's fine for exploration. It is hard to defend when a regulator asks why a decision was made, because the honest answer is "the agents talked until they converged." Prefer explicit edges when the answer has to be auditable — which is insurance and fintech, always.

The cost nobody prices

Every framework is a dependency with a release cadence, breaking changes, and abstractions you'll eventually read the source of. Week 2 priced 0.2 FTE for running an ANN service; a fast-moving agent framework isn't free either. For a small team it's a real recurring tax, and it belongs in the comparison.

5. The Chooser

python framework_chooser.py --decide --loops 0 --specialists 1 RECOMMENDATION: RAW — call the API in your own loop Nothing here needs a framework. No backward edges, no pause, no durability requirement, no second specialist. A tool-calling loop is ~40 lines you own outright. Adding a framework buys you abstractions for problems you do not have.
python framework_chooser.py --decide --loops 2 --human-approval --auditable RECOMMENDATION: GRAPH — LangGraph with a Postgres checkpointer Pausing for a human and surviving a crash are the same technical requirement: durable state, resumable at the exact node. Auditability reinforces this: explicit edges mean the path is a recorded fact, not an emergent property of a conversation.
The insight worth carrying into an interview
Pausing for a human and surviving a crash are the same technical requirement. Both need durable state that can resume at an exact node. That's why they're the two rows where RAW scores "rewrite" — and why, if either is on your list, the framework question is basically settled.

6. Three Domains

Retail — support agent

loops: 1 · human pause: rare
durable: no · audit: no

Graph, or honestly RAW. One clarification loop, sessions last minutes, a lost conversation is an annoyance not an incident.

This is the case where reaching for a framework is most often over-engineering — and where an interviewer will respect you for saying so.

Insurance — underwriting

loops: 2+ · human pause: yes
durable: weeks · audit: yes

Graph, no real argument. Every expensive row is checked: evidence-gathering loops, mandatory human review, cases that run for weeks, and a regulator who will ask why.

Crew is specifically wrong here — emergent control flow versus an audit requirement.

Fintech — disputes

loops: 1 · human pause: threshold
durable: days · audit: yes

Graph. Regulatory deadlines mean a run must survive restarts, and high-value disputes pause for a human.

The deadline is a hard external clock, which makes durable state a compliance property, not a convenience.
